KEY DIFFERENTIATOR: "Improve" Button

Without it:
  Design → Export → Manual optimization → Deploy
  (User guesses at improvements)

With it:
  Design → "Improve" → Suggestion shows:
    • What to add/change
    • Cost delta (e.g., -$200/mo)
    • Performance impact (e.g., +15% throughput)
    • Tradeoff explanation
  → Click apply → Design updates → Re-simulates automatically
  → Next suggestions evolve based on new design

This is what turns ArchSim from "cool learning tool" to "essential for teams"

RISKS & MITIGATION

Risk: Code generation quality is poor
  → Mitigate: Start with OpenAPI (spec-driven, less ambiguous)
             Test with 5 real users before shipping

Risk: Free tier gets saturated, doesn't convert to paid
  → Mitigate: Limit exports (e.g., 5 per month free)
             Make team features paid (code gen + sharing)

Risk: Cloud providers add competing features
  → Mitigate: Differentiate on design + teaching, not just code gen
             Focus on multi-cloud (our advantage)

Risk: Scope creep delays weeks 5-6
  → Mitigate: Ship weeks 1-4 as v2.0, roadmap weeks 5-6 as v2.5
